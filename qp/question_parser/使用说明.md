# 试卷 docx → 结构化题库：使用说明

## 一句话结论

**别用纯 Markdown，也别把整页存成图片。** 主存储是：

```
questions.jsonl  （交换/校对，一题一行 JSON）
questions.db     （App 内 SQLite，按 id 取题 / 全文检索）
assets/          （按内容 hash 去重的原图 + 公式图）
HTML 片段        （题干/选项/答案/详解各自的富文本，存在 JSON 字段里）
```

公式优先存成 **LaTeX 文本**（OMML 转换），老试卷里的 MathType 公式是图片，降级成**小尺寸内联公式图**。
Markdown 只留作人工编辑态；整题 SVG/PDF 只作为极少数复杂版式的兜底，不是主方案。

你给的这份样例跑完的结果：**14 题全部命中，答案/详解/选项/插图/公式位置正确，AI 兜底队列 0 条**。

## 目录

```
question_parser/
├── config.json          # 切题规则，换模板只改这里
├── parse_docx.py        # 主解析器（零第三方依赖）
├── omml_to_latex.py     # Word 自带公式 → LaTeX
├── build_db.py          # jsonl → SQLite
├── make_demo.py         # 生成自包含预览页
├── 使用说明.md
├── 题目预览.html         # 双击可看「一页一题 / 点答案 / 可复制」
└── build/
    ├── questions.jsonl
    ├── questions.db
    ├── report.csv            # 每题体检表
    ├── 待复核队列.jsonl       # 低置信题，交给 AI 兜底
    ├── 公式转LaTeX队列.jsonl  # 老式公式图清单，可一次性批量转 LaTeX
    ├── 汇总.json
    └── assets/               # 137 个文件
```

## 快速开始

```bash
cd question_parser

# 单份
python3 parse_docx.py --input "2026年11月9日.docx" --out build --config config.json

# 批量（递归找目录下所有 .docx，图片跨文档全局去重）
python3 parse_docx.py --input-dir ./我的试卷 --out build --config config.json

# 灌进 App 用的 SQLite
python3 build_db.py --jsonl build/questions.jsonl --db build/questions.db

# 生成本地预览页（可选）
python3 make_demo.py --jsonl build/questions.jsonl --out 题目预览.html --limit 6
```

运行环境：**Python 3.8+，零 pip 依赖**。唯一可选依赖是 ImageMagick（`convert`/`magick`），
用来把老式 WMF 公式图转成 PNG；没有它也能跑，只是保留 `.wmf` 原件并在报告里标注。
配置文件用 JSON 而不是 YAML，就是为了少一个依赖、拷走即跑。

## 数据字段

| 字段 | 说明 |
|---|---|
| `id` | `文档hash_q001`，全局唯一 |
| `source_doc` / `subject` / `section` / `number` | 来源、学科、章节、题号 |
| `type` | `single_choice` / `multi_choice` / `solution` / `fill_blank` / `short_answer` |
| `stem_html` | 题干 HTML 片段，插图、公式按原文顺序内联 |
| `options_html` | 4 个选项的 HTML 数组（解答题为空数组） |
| `answer_html` | 答案（点「答案」先显示这一层） |
| `explanation_html` | 详解（再展开这一层） |
| `images` | 引用到的图片清单：`src` / `kind` / `in` / 原始尺寸 |
| `formula_mode` | `latex` / `image` / `mixed` / `none` |
| `confidence` / `warnings` | 体检分与异常说明，低于阈值进复核队列 |

把「答案」和「详解」拆开是有意的：App 可以点一下只出 `C`，再点才出整段解析。

## 公式的三条路径

| 文档里的公式形态 | 处理方式 | 能否复制 |
|---|---|---|
| Word 自带公式（OMML，新式 docx） | `omml_to_latex.py` 转 LaTeX 文本，存 `q-math` 标签 | 能，直接复制 LaTeX |
| MathType OLE（本样例，118 个不同公式） | 抽出 WMF 矢量预览 → 转 PNG，按 hash 去重，内联 `<img class="q-formula">` | 暂不能，见下 |
| 纯文本 / 上下标字符 | 原样保留 | 能 |

**本样例恰好是第二种**：公式是 `Equation.DSMT4` 的 OLE 对象，正文里根本没有公式文字，
所以做不到无损转 LaTeX。这不是解析器的缺陷，是老式 Word 试卷的固有形态。
对应的解法是 `build/公式转LaTeX队列.jsonl`：118 张**去重后**的公式小图，一次性交给多模态模型
批量转 LaTeX，写回 `data-latex` 属性即可，之后所有文档复用，不需要每份再调 AI。
这正是「AI 只处理少数异常片段、不读整篇文档」的落点。

## 本次实测容量

| 项目 | 大小 |
|---|---|
| 原始 docx | 2940 KB |
| `questions.jsonl`（14 题全部文本+结构） | 66 KB |
| `questions.db`（含 FTS 全文索引） | 168 KB |
| 插图 19 张（真实题图，原样保留） | 2696 KB |
| 公式图 118 张（WMF→PNG，去重后） | 405 KB |
| assets 合计 | 3101 KB |

结论：**占空间的是真实插图，不是公式、不是文本**。公式是文本时几乎不占体积；
即便是这批老式公式图，118 张加起来也只有 0.4 MB，而且跨文档全局只存一份。
想再省：跑解析时加 `--webp`（需 Pillow）把大插图压成 WebP。

## App 端怎么接

1. **渲染**：WebView 加载 `stem_html` / `options_html` / `answer_html` / `explanation_html`，
   配一层响应式 CSS（`img{max-width:100%}`、公式 `vertical-align`）。手机端重排是特性，
   不是丢版式——保住的是段落、插图位置、公式内联顺序、选项层级这些**逻辑版式**。
2. **公式**：本地打包 KaTeX，启动时把 `<span class="q-math" data-latex="...">` 渲染成矢量公式；
   给每个公式加「复制 LaTeX」按钮。公式图有 `data-latex` 时同样可复制，没有时提示「图片公式」。
3. **取数**：SQLite 按 `id` 查一题一页；`questions_fts` 做搜索；`confidence` 排序做错题/复核入口。
4. **离线**：`assets/` 随包或首次启动下载，HTML 里用相对路径，外链图在解析阶段已落本地。
5. **保真兜底**：只对 HTML 还原不了的极复杂版式（大表格、多栏、化学装置图）额外导出单题 SVG/PDF，
   用 `render_mode` 字段标记回退。这一步本程序还没做，属于下一步扩展，不全局牺牲可复制性。

## 换模板怎么办

改 `config.json`，不动代码。常见的几处：

- 答案标记是 `【答案】` / `[答案]` / `答案：` → 改 `answer` 正则
- 详解标记是 `【详解】` / `解析` / `【解析】` → 改 `explanation` 正则
- 题号是 `1.` / `1、` / `第1题` → 改 `question` 正则
- 章节名、页脚噪声、表头 → 改 `section` / `noise`
- 题号不连续（比如按模块重新编号）→ `strict_sequence: false`
- 外链图不想下载 → `download_external: false`

解析器自带体检：题号连续性、答案非空、选项 4 个、图片引用存在、OMML 是否降级。
不过关的题写进 `待复核队列.jsonl`，只把这一两道题的纯文本片段发给 AI 修正，
token 从「每份全文 × 文档数」降到「少数异常片段」。本样例 14 题队列为空。

## 已知限制

- MathType 公式是图片，未批量转 LaTeX 前不可选中复制；这是源文档决定的。
- WMF 转 PNG 依赖 ImageMagick；缺失时保留 WMF，浏览器/App 需自行渲染或跑一次批量转换。
- 选项拆分假设「四个选项按 A→B→C→D 顺序出现」，优先用段首 `A．` 定位；
  解答/填空/计算题会自动跳过拆分。极端排版仍可能需人工校对，报告里会标出来。
- 切题依赖行首题号 + 连续性校验，若某份文档把题号写在表格里，需要扩展 `parse_docx.py` 的表格分支。
- 没有做单题 SVG/PDF 兜底导出（见「App 端」第 5 点）。

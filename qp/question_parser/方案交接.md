# 试卷 docx → 结构化题库：工程交接文档

> **面向**：接手完善 Python 解析器的 AI / 开发者
> **基线日期**：2026-11-10
> **验证样本**：`2026年11月9日.docx`（高中物理，12 页，14 题，含答案与详解）
> **当前状态**：规则解析全量跑通，14/14 题命中，AI 复核队列 0 条，程序可批量复用

---

## 0. 交接摘要

用户有大量「题目 + 答案 + 详解」型 docx 试卷，要做一个手机 App：每页一题，点击「答案」看答案，题目/答案里可能有公式与插图，**逻辑版式要保住**，且希望**程序一次写好、以后离线批量跑，不每份都调 AI**（降 token 成本）。

已定型的存储方案：

```
questions.jsonl   交换 / 人工校对，一题一行 JSON
questions.db      App 内 SQLite（按 id 取题 + FTS5 全文检索）
assets/           按 sha256 去重的图片（真实插图 + 老式公式图）
HTML 片段         题干/选项/答案/详解分别存在 JSON 字段里
```

**硬约束（接手时不要推翻）**：

1. 不用纯 Markdown 做主存储（表格、矩阵、选项缩进、图题混排会丢）；
2. 不把整页/整题截成图片做主存储（不可选中复制，与需求冲突）；
3. 不把「答案」和「详解」合并成一个字段（App 要先出 `C`、再展开解析）；
4. **不每份文档调 AI 读全文**。AI 只允许处理两类小片段：低置信异常题、去重后的公式小图；
5. 程序保持「零 pip 依赖、拷走即跑」；配置用 `config.json` 而非 YAML。

## 1. 目标边界

| 要做 | 不做 |
|---|---|
| 批量解析 docx → 结构化题目 | OCR 全量识别题图里的文字 |
| 保住段落、插图位置、公式内联顺序、选项层级 | 像素级复刻 A4 纸张版面（手机端应响应式重排） |
| 公式优先文本化（LaTeX），可复制 | 把公式永久当图片（只允许作为降级态） |
| 图片全局 hash 去重、外链图落本地 | 每份文档各存一份图 |
| 自检 + 低置信队列 | 承诺 100% 无需人工校对 |

**「版式保持不变」的准确解释**：保的是**逻辑版式**（题干→插图→选项的顺序、公式内联、上下标、分小题编号、段落层级），不是纸面坐标。手机屏幕宽度不固定，像素级复刻反而不可用。

## 2. 已实现 / 未实现

### 已实现

- docx 直接在 OOXML/XML 层读取，不依赖 LibreOffice 转 PDF；
- 章节、题号、答案、详解按可配置正则切分；题号连续性校验；
- 页眉页脚、`试卷第N页(共N页)`、`学校:/姓名:/班级:/考号:` 表头等噪声过滤；
- 选项 A/B/C/D 拆分，公式图用私有区占位符参与切分，不会错位；
- 解答/填空/计算/证明/实验题自动跳过选项拆分；
- Word 自带公式（OMML）→ LaTeX 文本，带降级标记；
- MathType OLE 公式（`Equation.DSMT4`）→ 抽 WMF 矢量预览 → 转 PNG → 按 hash 去重 → 内联；
- `w:drawing` 真实插图抽取、外链图下载落本地、原始尺寸记录（pt / px）；
- 图片跨文档全局去重；重复跑复用已转换的 PNG，不重启转换器；
- 答案缺失时从「故选 X」反推；
- 启发式置信度 + `待复核队列.jsonl` + `报告.csv` + `汇总.json`；
- `公式转LaTeX队列.jsonl`：去重后的公式小图清单，供一次性批量转换；
- jsonl → SQLite（含 FTS5）；
- 自包含 `题目预览.html`：一页一题、显示/收起答案、显示/收起详解、复制题干、点公式复制 LaTeX。

- 单题 SVG/PDF 保真兜底导出与 `render_mode` 回退；
- 表格内题号、多栏排版、化学方程式装置图的结构化；

- 真正的模型式置信度（当前是规则扣分）。

## 3. 架构与数据流

```
docx (ZIP)
  └─ word/document.xml ────┬─ w:p 段落 ─┬─ w:t        文本
                           │            ├─ m:oMath    OMML 公式 ──→ LaTeX 文本
                           │            ├─ w:drawing  插图 ───────→ assets/
                           │            └─ w:object   OLE 公式图 ──→ WMF→PNG → assets/
                           └─ word/_rels/document.xml.rels（rId → media/ 或外链 URL）
                                        │
                                        ▼
                          para_segments()  →  Seg 序列（text/math/figure/formula/break）
                                        │
                                        ▼
                     parse_document() 按正则切题 → stem/answer/explanation
                                        │
                                        ▼
                     render_paragraphs() → HTML 片段（图片用相对路径引用）
                                        │
                     ┌──────────────────┼──────────────────┐
                     ▼                  ▼                  ▼
          questions.jsonl        assets/*.png      report.csv / 队列 / 汇总
                     │
                     ▼  build_db.py
              questions.db (+ questions_fts)
                     │
                     ▼  App WebView + 本地 KaTeX + 响应式 CSS
```

**关键设计**：正文解析与渲染分离。`Seg` 是中间表示，HTML 只是其中一种输出；将来要出原生富文本、Flutter `WidgetSpan`、或单题 PDF，都从 `Seg` 分叉，不要从 HTML 反解析。

## 4. 数据契约（不要随意改字段名）

一题一条 JSON。字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | `文档名sha1前8位_q001`，全局唯一，作 SQLite 主键 |
| `source_doc` | str | 源文件名 |
| `subject` | str | 学科，由文档开头文本关键词猜测，可空 |
| `section` | str | 章节原文，如 `一、单选题` |
| `number` | int | 题号 |
| `type` | str | `single_choice` / `multi_choice` / `choice` / `solution` / `fill_blank` / `short_answer` |
| `stem_html` | str | 题干 HTML 片段，插图与公式按原文顺序内联 |
| `options_html` | list[str] | 4 个选项的 HTML；解答题为 `[]` |
| `answer_html` | str | 答案层（点击「答案」显示这一层） |
| `explanation_html` | str | 详解层（再展开这一层） |
| `images` | list[dict] | `{src, kind, in, w_pt, h_pt, w_px, h_px, latex?, ok?}`；`kind` ∈ `figure`/`formula`/`math`；`in` ∈ `stem`/`answer`/`explanation` |
| `formula_mode` | str | `latex` / `image` / `mixed` / `none` |
| `confidence` | float | 0–1，启发式 |
| `warnings` | list[str] | 异常说明 |

HTML 里的三类自定义标记，**App 渲染层依赖它们，改名要同步改**：

```html
<!-- OMML 转出的 LaTeX：可复制 -->
<span class="q-math" data-latex="\frac{1}{2}mg+{v}^{2}">\(...\)</span>

<!-- 老式公式图：data-latex 为空表示尚未转换；h_pt 用于按字号对齐基线 -->
<img class="q-formula" src="assets/xxx.png" alt="" data-latex=""
     data-h-pt="11.4" style="height:1.086em">

<!-- 真实题图 -->
<figure class="q-figure">
  <img class="q-figure-img" src="assets/yyy.png" alt="题图"
       style="max-width:100%;height:auto" data-w="420">
</figure>
```

真实样例（第 1 题，节选）：

```json
{
  "id": "e3b0c442_q001",
  "source_doc": "2026年11月9日.docx",
  "subject": "物理",
  "section": "一、单选题",
  "number": 1,
  "type": "single_choice",
  "stem_html": "<p>如图所示为橙子简易筛选装置……则（　　）</p><figure class=\"q-figure\"><img class=\"q-figure-img\" src=\"assets/cc2ce6317b18ee6a1eab.png\" alt=\"题图\" style=\"max-width:100%;height:auto\" data-w=\"420\"></figure>",
  "options_html": ["A．橙子受到每根杆的弹力方向不变", "B．……", "C．……", "D．……"],
  "answer_html": "<p>C</p>",
  "explanation_html": "<p>A．……故A错误；</p><p>C．离开杆后仅受重力……</p>",
```

## 5. 存储决策与容量实测

| 方案 | 结论 |
|---|---|
| 纯 Markdown + `$LaTeX$` | 只作人工编辑态。表格、矩阵、选项缩进、图题混排会丢 |
| 整页/整题截图 | 只作极少数复杂版式的兜底档，与「可复制」冲突，禁止做主存储 |
| **JSONL + SQLite + HTML 片段 + 独立图片** | **主方案** |

本次实测（同一份 docx）：

| 项目 | 大小 |
|---|---|
| 原始 docx | 2940.3 KB |
| `questions.jsonl`（14 题全部文本与结构） | 66.2 KB |
| `questions.db`（含 FTS5 索引） | 168.0 KB |
| 真实插图 19 张 | 2696.0 KB |
| 公式图 118 张（WMF→PNG，去重后） | 405.0 KB |
| `assets/` 合计 137 文件 | 3101.0 KB |

**结论**：占空间的是真实插图，不是公式也不是文本。公式是文本时几乎零体积；即便是 118 张老式公式图也才 0.4 MB，且跨文档全局只存一份。需要再省就给大插图压 WebP（`--webp`，需 Pillow，属可选依赖）。

## 6. 配置契约 `config.json`

换模板**只改这里，不改代码**。全部是 Python 正则字符串（JSON 里反斜杠要双写）。

| 键 | 作用 | 当前值要点 |
|---|---|---|
| `section` | 章节行 | `^[一二三…]、\s*(单选题\|多选题\|…)$` |
| `question` | 题号行首 | `^\s*(\d{1,3})\s*[.．、]\s*`，**必须有捕获组 1 = 题号** |
| `answer` | 答案标记 | 兼容 `【答案】` / `[答案]` / `答案：`；**捕获组 1 = 答案正文** |
| `explanation` | 详解标记 | 兼容 `【详解】/解析/解答/分析`；**捕获组 1 = 标记词，捕获组 2 = 正文**（`drop_prefix` 用的是 `m.start(2)`） |
| `option` | 选项标记 | `([ABCD])\s*[.．、]` |
| `noise` | 噪声行正则数组 | 页码、`学校:/姓名:` 表头、空行 |
| `subject_keywords` | 学科关键词 | 只扫文档开头 40 个 `w:t` |
| `strict_sequence` | 题号必须 `n == last+1` | `true`；按模块重新编号的文档改 `false` |
| `confidence_threshold` | 进复核队列阈值 | `0.85` |
| `download_external` | 外链图是否落本地 | `true`（**App 离线必须开**） |
| `formula_convert` | WMF→PNG | `true` |
| `formula_density` | 转换 DPI | `300` |
| `webp` | 位图压 WebP | `false` |

命令行开关：`--input` / `--input-dir`（递归 `*.docx`，跳过 `~$` 临时文件）/ `--out` / `--config` / `--no-formula-convert` / `--webp`。

## 8. 公式的三条路径（本次最重要的发现）

| 源文档形态 | 处理 | 可复制 |
|---|---|---|
| Word 自带公式 OMML（`m:oMath`） | `omml_to_latex.py` → LaTeX 文本 → `q-math` | 是 |
| **MathType OLE（`Equation.DSMT4`），本样例即此** | `w:object` → `v:imagedata r:id` → WMF → ImageMagick 转 PNG → 内联 `q-formula` | 转换前否，转换后写回 `data-latex` 即是 |
| 纯文本上下标字符 | 原样保留 | 是 |

**本样例正文里根本没有公式文字**：`oMath` 计数为 0，有 160 个 `w:object`、118 张不同的 WMF 公式预览图。这不是解析器缺陷，是老式 Word 试卷的固有形态，因此**不可能做到无损文本化**，必须走「一次性批量识别」：

1. 解析产出 `build/公式转LaTeX队列.jsonl`，每行含 `src` / `original_ext` / `w_pt` / `h_pt` / `occurrences`；
2. 把**去重后的 118 张小图**一次性交给多模态模型，批量返回 LaTeX；
3. 写回 `questions.jsonl` 中对应 `<img class="q-formula">` 的 `data-latex`，并同步更新 `questions.db`；
4. 之后所有文档复用同一张 hash→LaTeX 映射表，**不再逐份调 AI**。

这条正是「AI 只处理少数片段、不读整篇文档」的落点。本样例规则全命中，复核队列为空，唯一值得调 AI 的就是这一步。

## 9. 已踩过的坑（必读，别重复踩）

1. **OOXML 关系属性必须带花括号**：`r:embed` 是 `{http://schemas.openxmlformats.org/officeDocument/2006/relationships}embed`。曾误写成 `NS['r'] + 'embed'`（少了 `{}`），结果所有图片静默丢失、解析出 14 题但 `assets=0`。改这里务必用 `R_EMBED`/`R_LINK`/`R_ID` 三个常量。
2. **`Seg` 构造别传 `kind` 关键字**：`Seg(kind, src, **meta)` 里 `meta` 若含 `kind` 会报 `multiple values for argument 'kind'`。元数据里只放尺寸和 `src`。
3. **SQLite 在部分容器/网络盘报 `disk I/O error`**：默认回滚日志写不了。`build_db.py` 已加 `PRAGMA journal_mode=MEMORY / locking_mode=EXCLUSIVE / synchronous=OFF / temp_store=MEMORY`，别删。
4. **纯图片段落不能当空段丢**：题图常独占一个 `w:p`，`para.text` 为空。主循环用 `has_media` 判断保留，否则插图全丢。
5. **解答题不能跑选项拆分**：否则会误报「未找到段首 A 选项 / 选项不足 4 个」并拉低置信度。`split_options(stem_paras, is_choice)` 已按 `section` 关键字跳过。
6. **答案只有公式图时 `answer_plain` 为空**：不能据此判「答案缺失」，已改用 `has_content(ans_p)`。
7. **详解正则用 `m.start(2)`**：`group(1)` 是「详解/解析」标记词，`group(2)` 才是正文；用错会把标记词切进正文。
8. **WMF 转换要缓存**：137 张图首次转换耗时明显；`AssetStore.store()` 会先查 `assets/<hash>.png`，重复跑/批量跑直接复用，别去掉这层。
9. **外链图必须落本地**：源文档里存在 COS 上的图 URL，不下载 App 离线打不开；下载失败要进 `warnings` 而不是静默吞掉。
10. **`drop_prefix` 按字符数删**：目前标记都在段首纯文本，安全；若将来标记前出现公式/图片段，需改成按 `Seg` 边界删。
11. **不要在主循环里用 `text = raw.strip()` 去做题号/答案匹配**：原始行首空格与全角括号会影响正则，主循环已改用 `raw` 匹配、`text` 只做噪声判断。

```python
import json, sqlite3
from pathlib import Path
b = Path('build')
qs = [json.loads(l) for l in open(b / 'questions.jsonl', encoding='utf-8')]
assert len(qs) == 14, '题数变了'
assert [q['number'] for q in qs] == list(range(1, 15)), '题号不连续'
assert all(q['answer_html'].strip() for q in qs), '有答案缺失'
assert all(len(q['options_html']) == 4 for q in qs[:12]), '选择题选项不是 4 个'
assert all(len(q['options_html']) == 0 for q in qs[12:]), '解答题被误拆选项'
assert all('试卷第' not in q['stem_html'] for q in qs), '页脚噪声没清干净'
assert sum(1 for _ in open(b / '待复核队列.jsonl', encoding='utf-8')) == 0, '产生了新的低置信题'
for q in qs:
    for img in q['images']:
        if img['src']:
            assert (b / img['src']).exists(), '图片引用悬空: ' + img['src']
con = sqlite3.connect(b / 'questions.db')
assert con.execute('select count(*) from questions').fetchone()[0] == 14
print('回归通过')
```

**容量红线**：`questions.jsonl` 应稳定在 60–80 KB 量级；若暴涨说明把图片 base64 塞进 JSON 了，属于设计倒退。

## 12. App 端接口约定

| 能力 | 做法 |
|---|---|
| 取一题 | `SELECT * FROM questions WHERE id = ?`；分页用 `source_doc, number` 排序 |
| 搜索 | `questions_fts`（FTS5），`plain()` 会把公式转成 LaTeX 文本、图片转成 `[图]` 占位 |
| 渲染 | WebView 加载 `stem_html` / `options_html` / `answer_html` / `explanation_html`，配一层响应式 CSS：`img{max-width:100%;height:auto}`、公式 `vertical-align` 按 `data-h-pt` 换算 `em` |
| 公式 | 本地打包 KaTeX；把 `q-math[data-latex]` 渲染成矢量；给每个公式加「复制 LaTeX」。`q-formula[data-latex]` 非空时同样可复制，为空时提示「图片公式」 |
| 交互 | 点「答案」→ 显示 `answer_html`；点「详解」→ 再显示 `explanation_html`（两层分开，别合并） |
| 图片 | `assets/` 随包或首次启动下载；HTML 里是相对路径，WebView 用 `file://` 或本地资源拦截 |
| 离线 | 外链图已在解析阶段落本地，App 不依赖网络 |
| 兜底 | 未来 `render_mode != 'html'` 时加载 `fallback_src`（SVG/PDF），仅对该题牺牲复制 |
